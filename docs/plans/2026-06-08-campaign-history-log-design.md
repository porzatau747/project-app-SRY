# รายละเอียดการออกแบบระบบคลังแคมเปญย้อนหลัง (Campaign History Log Design Specification)

**Date:** 2026-06-08  
**Topic:** Campaign History Log (Global Sidebar Drawer)  
**Status:** Approved by User  

---

## 1. จุดประสงค์ของระบบ (Goal & User Value)
ช่วยให้ผู้ดูแลเพจ Advice สามร้อยยอด สามารถเก็บรักษา ค้นหา และกู้คืนคอนเทนต์หรือ Prompt เจนภาพที่ AI เคยสร้างขึ้นมาได้ย้อนหลัง โดยไม่ต้องกลัวข้อมูลสูญหายเมื่อเปลี่ยนหน้าหรือปิดบราวเซอร์ และเพื่อลดการสิ้นเปลืองโควตา Gemini API ในการสร้างคอนเทนต์ซ้ำ

---

## 2. โครงสร้างสถาปัตยกรรมข้อมูล (Data Architecture)
ระบบจะใช้คีย์เก็บข้อมูลลงในบราวเซอร์ผ่าน `localStorage` โดยกำหนดประเภทข้อมูลดังนี้:

```typescript
export interface HistoryItem {
  id: string;          // รหัส ID เฉพาะตัว (Timestamp / UUID)
  timestamp: string;   // วันและเวลาที่สร้างคอนเทนต์ (ISO String)
  pageType: 'stock' | 'trend' | 'combo' | 'creator'; // ประเภทหน้าผู้สร้าง
  title: string;       // หัวข้อหลักหรือสินค้าของแคมเปญ
  result: string;      // ข้อความ Caption หรือ Prompt เต็มรูปแบบที่สร้างสำเร็จ
  inputState: any;     // เก็บค่าฟอร์มอินพุตเพื่อกดกู้คืนกลับมาแก้ไขต่อได้
  isPinned: boolean;   // ระบุว่าเป็นรายการที่ปักหมุดตรึงไว้ (ห้ามลบหมุนเวียน)
}
```

- **ขีดจำกัดประวัติ:** จัดเก็บสูงสุด **15 รายการล่าสุด** (FIFO) หากเกินจากนี้ รายการเก่าสุดที่ไม่ได้ปักหมุดตรึง (`isPinned: false`) จะถูกลบออกโดยอัตโนมัติ

## 3. หน้าจอการแสดงผล (UI & Layout Design)
- **History Toggle Button:** เพิ่มปุ่มไอคอนรูปนาฬิกาประวัติย้อนหลัง 🕒 แบบเรืองแสงสีฟ้านีออนสะท้อนแสง วางอยู่ถัดจากแถบนำทาง [topNav] ของทุกหน้า
- **Global Sidebar Drawer:**
  - แผงควบคุมสไลด์ด่วนเปิดจากขอบขวาของหน้าจอ ขนาดความกว้าง `380px`
  - สกินพื้นหลังกระจกเบลอมืดสนิท (`rgba(10, 15, 30, 0.95)`, `backdrop-filter: blur(20px)`) ขอบสีฟ้านีออนเรืองแสงสะท้อนตาเข้ากับแอป Cyber Grid
  - ใช้ CSS transition เพื่อให้แถบลิ้นชักเลื่อนปิด-เปิดได้อย่างนุ่มนวล
- **History Cards:**
  - แสดงลิสต์แยกสีตามหน้าผู้สร้าง: Cyan (สต็อก), Green (เทรนด์), Purple (คอมโบ)
  - แสดงปุ่มดาวสีเหลืองนีออนเรืองแสง ⭐ เพื่อกดตรึง/ปักหมุด

## 4. ปฏิสัมพันธ์และการไหลของข้อมูล (Interactive Workflows)
1. **การสร้างและบันทึกประวัติ (Save Flow):**
   - ทุกครั้งที่ผู้ใช้กดปุ่มสร้างคอนเทนต์ด้วย Gemini และได้ผลลัพธ์สำเร็จ ระบบจะเรียกใช้ฟังก์ชัน `saveToHistory`
   - เพิ่มรายการใหม่ที่ส่วนบนสุดของลิสต์ คอนฟิกค่าสถานะให้เรียบร้อย และเซฟลง `localStorage`
2. **การกู้คืนฟอร์มเดิม (Restore Flow):**
   - เมื่อกดปุ่ม "กู้คืนฟอร์ม" ระบบจะเรียกใช้ฟังก์ชันกู้คืนสถานะ ฟิลด์ของหน้าที่กำลังเปิดจะถูกกรอกย้อนหลังด้วยข้อมูลใน `inputState` ทันที
3. **การลบและตรึงรายการ (Manage Flow):**
   - กดปุ่ม ⭐ เพื่อสลับสถานะ `isPinned` ของการ์ดใบนั้น ๆ
   - กดปุ่ม 🗑️ เพื่อลบการ์ดใบนั้นออกจากคลังประวัติทันที

## 5. แผนการตรวจสอบความเสถียร (Verification Plan)
- **Automated Tests:**
  - รันการทดสอบฟังก์ชันจัดการข้อมูลประวัติ `historyUtils` ผ่าน vitest เพื่อเช็กความถูกต้องของการเพิ่ม, ลบ, ปักหมุด และควบคุม FIFO 15 รายการ
- **Manual Verification:**
  - เปิดแอปพลิเคชัน ทดลองเรียกดูประวัติและคลิกคัดลอก/ติดดาว ตรวจสอบข้อมูลหลังปิดเปิดหน้าเว็บใหม่
